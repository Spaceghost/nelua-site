Nelua ecosystem measurements · 21 November 2026

Read summary.csv for medians, inclusive quartiles, minimum, maximum and units.
The raw CSVs include the warm-up where it was recorded (round zero). Each
comparison used fresh, interleaved processes on the same host. These are warm
filesystem results. Other host activity contributed to wide wall-time ranges.
No installation telemetry or workload-frequency counts were available.

Priorities and coverage

* Cascadia Core. Boot-to-command runs once per VM launch. Changing the local
  compression of the release initramfs saved 2.27 s at the median in TCG.
  The direct-shell control also used the same kernel and cpio. It bypasses
  service startup, including the fixture's requested 350 ms failed readiness
  check. It is a diagnostic lower bound, not an equivalent production boot.
  Theseus Init is a related project outside Nelua core.
* Generated Lua VM. Switch dispatch occurs on every interpreted bytecode.
  The table improvement saved 108 ms per million-call run and 93 ms during
  a fresh Nelua matrix C emission with this interpreter configuration.
  TinyCC still led by 329 ms on the million-call input and 238 ms on the
  frontend workload. This comparison applies to an interpreter whose VM
  was compiled by necc; the system Nelua compiler uses its own interpreter.
* Nelibc. Search is a library primitive and the distribution matters.
  The alternating 64 KiB memmem miss saved 215 us/call. The interior-byte
  miss saved 126 us/call. The 63-byte-run miss already took about 1 us.
  Early long-needle memmem hits became more expensive. See all 33 rows per
  round for text, seeded random data, binary data, hits and misses.
* Native Nelua and necc compilation. Building the real Lua VM translation
  unit still took 138 ms with necc versus 24 ms with the SDK TinyCC. Fork
  versus upstream release compilation differed by workload. Trying -O3
  for the bundled Lua interpreter gave mixed results; frontend-flags.csv
  compares it with the default -O2 in seven interleaved rounds, including
  byte-identical C checks. No compiler flag change was shipped.
* nelinker. The current standalone build linked the full Lua interpreter in
  10.71 ms versus TinyCC's 16.31 ms. Their peak RSS differed by 4 KiB.
  nebuild was competitive on unchanged targets; Ninja led by 0.81 ms on
  the larger manifest. These timings do not establish a scheduling gap.
* Inventory. The Core index covers the compiler, Nelibc, necc, nelinker,
  nebuild, neboot and the Nebox userland including nsh. The established
  compiler frontend, C-toolchain, linker/archive, unchanged-build and libc
  tables remain available on their project pages. The neboot page records
  an OVMF boot qualification. Direct kernel boot here exercises no EFI
  menu. The Workshop also lists Drift, Atlas firmware, melodica.h,
  libc.bend and Writ. They supply no matched timing table on the index.

standalone program execution and execution of the mixed interpreter have

uses neboot b8c56a815f6e07beb7abdad9339568790594d4d4. Four fresh boots
