Native Extensible Lua, all the way down

Nelua, with its own libc and userland

One language from the compiler to the shell prompt: a Nelua compiler fork, a C library written in Nelua, and a toybox-style userland linked against it.

Nelua is a statically typed, metaprogrammable systems language with Lua syntax that compiles to C. This site tracks the three pieces that make it self-sufficient, the workshop libraries built on top of them, and the wider Nelua world they sit in. Every number here comes from a recorded run; nothing is claimed that was not observed.

How much is ours, how correct is it, and how fast?

The goal is the fastest correct implementation of the libc operations programs use most. The current evidence compares glibc, musl and Cosmopolitan, each alone and with Nelibc, on the same host and consumer.

Completion

glibc: 819; musl / Zig: 793; Cosmopolitan: 399 of 1,471 tracked names exported by Nelibc. These count owned implementations, not standards compliance. Cosmopolitan deliberately delegates more stateful services.

Conformance

glibc: 301 → 325 passes; musl / Zig: 327 → 333 passes; Cosmopolitan: 279 → 302 passes in the matched functional, regression and math corpus. Build failures, runtime failures and newly failing tests are all reported.

Performance

Synthetic record parser, baseline time ÷ Nelibc time: glibc 0.75×; musl / Zig 2.23×; Cosmopolitan 2.46×. Above 1× is faster. The detailed results include memory, strings, conversion, math, allocation, formatting and sorting, including slower cases and delegated calls.

Measured 2026-11-17 UTC; Intel(R) Core(TM) i5-10400 CPU @ 2.90GHz; 7 process rounds, one pinned CPU on a shared host. Consumer checks passed before timing. Single-host microbenchmarks do not establish a globally fastest libc.

Optimization follow-up: memchr-absent(32) 2.04×; strtol-decimal 1.51×; qsort-128-integers 1.65× faster than the previous candidate in the concurrent GCC/glibc comparison. Slower cases and alignment results are included on the detailed page.

Builds verified. The glibc, musl and Cosmopolitan builds pass integration checks. Standalone builds and Bend’s worker pool pass too. Test results and known gaps.

Three rings

The core is what the language needs to stand on its own. The workshop is what gets built here with it. The world is everything upstream and around it. The rings are kept apart on purpose: core pieces depend only on each other, workshop pieces depend on the core, and nothing in the core depends on the outer rings.

01 Core

The language and the two things every program needs: a C library and a userland. All three are Nelua.

  • Nelua compilerSpaceghost/nelua-lang: upstream Nelua plus variants, optionals, an exhaustive match, owned records with move, closures, structured compile-time evaluation, compile-time syntax extensions (#syntax), const pointers, a freestanding pragma, --target and bindgen. See how reusable record configs become static data ↗ · Explore the syntax extensions and full guide ↗
  • nelibcA C library rebuilt piece by piece in Nelua. Hybrid archives over glibc, musl or Cosmopolitan, a standalone Linux x86-64 runtime, and a host profile for kernels.
  • neboxA toybox-style multicall binary: 104 applets including an interactive POSIX shell, awk, sed, sort, find and GNU-exact diff and patch, one static executable, no host libc. Linked against nelibc standalone; checked case by case against GNU coreutils, gawk and dash.

02 Workshop

Libraries and programs built here on the core. They consume the compiler and nelibc; they are not part of them.

  • DriftDevice drivers that travel between operating systems: Virtio, xHCI, NVMe, Ethernet and AHCI in Nelua, linked as generated C into any kernel.
  • Atlas firmwareESP32-S3 LoRa field controller where Nelua owns the bounded native mechanisms beside system Lua and ESP-IDF.
  • melodica.hA Pandora protocol library with five implementations behind one C ABI; one of them is Nelua.
  • libc.bendThe same libc idea in Bend 2, resting on nelibc. nelibc's host profile is what the Bend runtime boots on.
  • WritInformation-flow control in Bend 2; the first consumer of nelibc's host profile.

Why keep a libc and a userland in the language

A systems language is only as portable as the runtime beneath it. With nelibc the program, its C library and its startup code are all Nelua, compiled by one toolchain to one static binary. nebox is the proof: a working shell and toolbox, 3,013,304 bytes (recorded 2026-11-08), with nm -u empty. When a nelibc function misbehaves the fix is a Nelua edit, and the same compiler fork builds every layer.

Build everything

Nelua (the fork), Zig for zig cc, and a Linux x86-64 box. GCC and TinyCC are comparison profiles.

Evidence standard

Runtime-free by construction

The fork's pragmas.freestanding rejects heap, process, stdio and main symbols at compile time. nelibc's host profile and Drift's kernel example are built that way: no GC, no allocator, no entry point unless you ask for one.
