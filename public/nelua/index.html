Native Extensible Lua, all the way down

Nelua, with its own libc and userland

One language from the compiler to the shell prompt: a Nelua compiler fork, a C library written in Nelua, and a toybox-style userland linked against it.

Nelua is a statically typed, metaprogrammable systems language with Lua syntax that compiles to C. This site tracks the three pieces that make it self-sufficient, the workshop libraries built on top of them, and the wider Nelua world they sit in. Every number here comes from a recorded run; nothing is claimed that was not observed.

Three rings

The core is what the language needs to stand on its own. The workshop is what gets built here with it. The world is everything upstream and around it. The rings are kept apart on purpose: core pieces depend only on each other, workshop pieces depend on the core, and nothing in the core depends on the outer rings.

01 Core

The language and the two things every program needs: a C library and a userland. All three are Nelua.

  • Nelua compilerSpaceghost/nelua-lang: upstream Nelua plus variants, optionals, an exhaustive match, owned records with move, closures, compile-time evaluation, compile-time syntax extensions (#syntax), const pointers, a freestanding pragma, --target and bindgen.
  • nelibcA C library rebuilt piece by piece in Nelua. Hybrid archives over glibc or musl, a standalone Linux x86-64 runtime, and a host profile for kernels.
  • neboxA toybox-style multicall binary: 88 applets including an interactive POSIX shell, awk, sed, sort, find and a GNU-exact diff, one static executable, no host libc. Linked against nelibc standalone; checked case by case against GNU coreutils, gawk and dash.

02 Workshop

Libraries and programs built here on the core. They consume the compiler and nelibc; they are not part of them.

  • DriftDevice drivers that travel between operating systems: Virtio, xHCI, NVMe, Ethernet and AHCI in Nelua, linked as generated C into any kernel.
  • Atlas firmwareESP32-S3 LoRa field controller where Nelua owns the bounded native mechanisms beside system Lua and ESP-IDF.
  • melodica.hA Pandora protocol library with five implementations behind one C ABI; one of them is Nelua.
  • libc.bendThe same libc idea in Bend 2, resting on nelibc. nelibc's host profile is what the Bend runtime boots on.
  • WritInformation-flow control in Bend 2; the first consumer of nelibc's host profile.

03 World

Upstream and the community. The fork tracks upstream closely and sends what it can back.

  • nelua.ioThe language's home: tutorial, overview, manual, and the standard libraries that ship with the compiler.
  • edubart/nelua-langUpstream. This fork's base is commit a584505 from 2025-06-24.
  • nelua-batteries · nelua-decl · neneExtra libraries, C binding generation, and a 2D game engine from upstream's author.
  • DiscordWhere the Nelua community talks.

Why keep a libc and a userland in the language

A systems language is only as portable as the runtime beneath it. With nelibc the program, its C library and its startup code are all Nelua, compiled by one toolchain to one static binary. nebox is the proof: a working shell and toolbox, about 1.5 MB, with nm -u empty. When a nelibc function misbehaves the fix is a Nelua edit, and the same compiler fork builds every layer.

Build everything

Nelua (the fork), Zig for zig cc, and a Linux x86-64 box. GCC and TinyCC are comparison profiles.

git clone https://github.com/Spaceghost/nelua-lang
make -C nelua-lang
git clone https://github.com/Spaceghost/nelibc
make -C nelibc lib-standalone-zig
git clone https://github.com/Spaceghost/nebox
make -C nebox NELIBC=../nelibc test

Runtime-free by construction

The fork's pragmas.freestanding rejects heap, process, stdio and main symbols at compile time. nelibc's host profile and Drift's kernel example are built that way: no GC, no allocator, no entry point unless you ask for one.
