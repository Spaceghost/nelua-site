Core

nebox

A toybox-style userland: 104 applets including a POSIX shell, one static binary, no host libc.

Spaceghost/nebox is a multicall binary written in Nelua and linked against nelibc's standalone archive. Each applet is chosen from argv[0] (a hard or symbolic link named after the applet) or from the first operand. It carries its own POSIX shell, regex engine, awk, stream editor, sort, find, diff and checksum implementations, all in Nelua.

How it is checked

Every case in tests/run.sh runs one shell command twice from identical fixture trees: once with the host's GNU coreutils, once with nebox's applet links first on PATH. stdout, the exit status and a snapshot of the resulting directory (names, modes, checksums) must match. Where the host has no reference tool, a pinned expected output is used instead.

Link recipe

Nelua emits C; zig cc links the whole nelibc standalone archive with no libc, no PIE and nelibc's own _start.

nelua -r --cc 'zig cc -mcpu=x86_64' \
  --cflags='-DNELIBC_STANDALONE -nostdlib -static \
    -ffreestanding -fno-builtin -Wl,-e,_start' \
  --ldflags='-Wl,--whole-archive \
    libnelibc-standalone-zig.a -Wl,--no-whole-archive' \
  -o nebox src/nebox.nelua
nm -u nebox   # must print nothing

What the GC situation is

The program is compiled with pragmas.nogc: nelibc has no _setjmp, which Nelua's collector needs, and a shell toolbox does not need a collector. Applets allocate with the default allocator and exit; memory is reclaimed by the kernel.

Own regex engine

POSIX basic and extended syntax with brackets, classes, intervals, groups, alternation, back-references and the GNU word escapes, as a Pike VM with GNU leftmost-longest semantics in src/nebox/regex.nelua: earliest start wins, then the longest match. grep, sed, awk, expr and find share it.

An interactive shell: sh and nsh

sh -i, or sh on a terminal, reads commands through nebox's own line editor: lines that wrap past the terminal width, UTF-8 cursor motion, emacs keys with a kill buffer, history in HISTFILE with Ctrl-R search, Tab completion of commands, files and $NAMEs, and bracketed paste. Errors return to the prompt as POSIX asks, Ctrl-C ends the command being typed or run, Ctrl-Z, fg, bg and jobs do job control, and ENV runs at startup. nsh is the same shell with a coloured prompt and XDG history and rc files: see it in action. Recovery from errors uses nelibc's new <setjmp.h>.

GNU's option parser, and the gaps it found

Most applets now parse options through a port of glibc's getopt_long: options after operands, GNU's long names with unique abbreviations and glibc's ambiguity rules, and the long options nebox lacks refused by name instead of misread. Comparing against GNU turned up applets that accepted options and ignored them; cat, fold, rmdir, chmod (over gnulib's modechange.c, umask rules included), tr, cut, uniq, head, tail (with -f/-F following), nl, comm, paste, timeout (process groups and signal forwarding), tee, mktemp, readlink and realpath (over gnulib's canonicalizer), sort, wc, id, expand, unexpand, split (every -n chunk mode and --filter), shuf (byte-identical with GNU under --random-source, reservoir sampling included) stat (every directive, over new ports of gnulib's quotearg and mount-list code), rm and du (over a traversal that reproduces what gnulib's fts hands them), ln (with gnulib's backup-name logic), df (with a port of gnulib's human.c), chown and chgrp (over a shared fts iterator), cp, mv and install (over one port of copy.c: reflinks, sparse extents, hard-link maps, xattrs, backups, cross-device moves), touch and truncate, echo, nproc, sleep, printenv, tac (separators as regular expressions), tsort, test and [, env (-S split strings and the signal options), printf (the shell's builtin too, %a as glibc prints x87 long doubles), expr (arbitrary-precision arithmetic, glibc's regex messages) factor (any length, with GNU's output order through pipes), cmp (diffutils), od, sort (keys, -R, --debug, merge), xargs (findutils, -P included) ls (every 9.1 option, colors and --dired; plus dir and vdir), date (with all of gnulib's parse-datetime, --debug included), grep (GNU grep 3.8: binary files, -r with include/exclude, colors) sed (GNU sed 4.9, with its error positions), find (findutils 4.9.0, -printf and -exec + included), hexdump and hd (util-linux 2.38.1 with its -e format language), rev, strings (binutils 2.40), groups, which, sync free and kill (procps 4.0.2), and hostname (Debian 3.23, with dnsdomainname/domainname, over a port of glibc's resolver path) are now ports of their coreutils sources, each checked against GNU on hundreds to thousands of random cases.

dd, join, checksums and encodings, ported from coreutils

dd follows GNU coreutils 9.1's dd.c: every conversion including the EBCDIC tables, block and unblock, swab and sparse; every flag (fullblock, count_bytes, direct, nocache, ...); GNU's number syntax with kB/KiB, B and x; bs= passing each read through while ibs/obs regroup; the statistics lines with gnulib's rounding, status=progress, and reports on SIGUSR1 and Ctrl-C. join ports join.c, down to the obsolete -j1 ARG operand rules, on top of a port of glibc's getopt_long. The nine checksum tools (md5sum, sha1sum to sha512sum, b2sum, cksum, sum) are one port of digest.c over nebox's own streaming MD5, SHA-1, SHA-2, BLAKE2b, SM3 and CRC code, with --tag, -z, escaped names and GNU's check-file parser. base64, base32 and basenc port basenc.c with gnulib's decoders, all eight encodings included. Comparisons against GNU on 754 dd, 1,596 join, 1,989 checksum and 2,588 encoding cases found no difference in output, diagnostics, exit status or files left behind.

patch, read from GNU's source

patch places hunks with GNU patch 2.7.6's own search (offsets outward, then fuzz), detects reversed patches and asks GNU's questions, rebuilds rejects the way GNU does, and backs files up when a patch did not match exactly. A fuzzer feeds both programs random diffs in three formats against shifted, edited and already-patched files: 2,000 cases with identical output, status, result, reject and backup files.

diff, step for step with GNU

diff ports GNU diffutils 3.8's analysis: identical ends trimmed on bytes with horizon lines, lines of one file with no match in the other discarded first, the middle-snake divide and conquer with its cost cut-off, and boundary shifting. The edit scripts are GNU's: a fuzzer compares both on random files for twelve option sets, 24,000 comparisons without a difference, and 40,000-line files with heavy changes match too.

Known limits

Stated rather than worked around. The full list is in the repository's README.

  • No multibyte locales anywhere: strings are bytes, collation is byte order, -i folds ASCII.
  • sh is a POSIX shell checked against dash by 444 cases: the full grammar, expansions, redirections, traps and the special and regular builtins. Interactive use, job control included, is tested on a pseudo-terminal (24 sessions); fc, vi mode and ulimit are not implemented. Where POSIX and dash disagree, nebox follows POSIX and the case is pinned.
  • awk is POSIX awk checked against GNU Awk 5.2.1 --posix; GNU extensions such as gensub, strftime and BEGINFILE are not there, and RS uses only its first character.
  • date follows GNU date's formatting rules in local time (TZif files, POSIX TZ strings, TZDIR), and -d reads a subset of gnulib's parse-datetime (ISO and US dates, times with zones and am/pm, @SECONDS, yesterday, weekdays, 3 days ago, next month, GNU's quirk that +1 after a time is a zone); month names, ordinal words, -I, --rfc-3339, -f and setting the clock are not there.
  • ls lays out columns like GNU ls 9.1 (-C, -x, -m, -w, TABSIZE) but has no quoting styles, colour, -L/-H or BLOCK_SIZE. du and find walk directories in sorted name order where GNU uses directory order.
  • sed has -z, M and e but no --posix, -u, v or the \d \o \x \c escapes; grep has GNU context lines, -z -Z -L -f -s and -o -w as GNU prints them, but no long options or binary-file detection; sort has the GNU option surface (-k modifiers, -h, -V) but no -M; xargs has no -P. seq matches GNU seq 9.1 for floats, -f, -w and integers past 264.
  • tail -f polls once a second. timeout polls the child every 2 ms instead of using signals.
  • Names for ids come from reading /etc/passwd and /etc/group directly (nelibc's new getpwuid reads the same files).
  • diff has normal, context, unified and ed output and -i -b -w -B -a -N -q -s -r, but no long options, -p, -y, -D or -I.

make -C nebox NELIBC=../nelibc        # build/nebox
make -C nebox NELIBC=../nelibc test   # the conformance suite
