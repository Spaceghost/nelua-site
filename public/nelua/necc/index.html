necc

Build C and Nelua programs for x86-64 Linux against standalone Nelibc, run Lua, or compile an object for UEFI firmware.

Compile a program

These commands assume the staged SDK is installed at the distro default or selected with NECC_SYSROOT.

export NECC_SYSROOT=/path/to/sdk
printf '%s\n' 'int main(void) { return 0; }' > hello.c
necc hello.c -o hello
./hello

printf '%s\n' "print 'hello from Nelua'" > hello.nelua
necc hello.nelua -o hello-nelua
./hello-nelua

necc --lua -e 'print(_VERSION)'

For a multi-file link, pass source files, object files and static archives together. Put archives after the objects that use them. Use -c to keep the object file from a single input.

Choose a Nelua compilation path

  • necc program.nelua uses the full Nelua frontend and TinyCC as its C backend.
  • necc --native program.nelua sends the full frontend’s generated C through necc’s native C frontend. This path requires the program’s generated C to fit the supported subset.
  • necc --direct program.nelua selects the self-hosted Nelua subset frontend and the native C backend.

The C frontend is written in Nelua. Its native backend uses the x86-64 System V calling convention by default.

Call x86-64 UEFI firmware

When the Nelua frontend emits C for an EFI entry point or protocol function pointer, necc honors its ms_abi attribute. Firmware can call the entry point, and the application can call firmware through a pointer stored in a protocol table.

The neboot verification exercises both directions. The compiler emits an ELF object for nelinker’s EFI output mode.

Link with nelinker

The 19 November 2026 toolchain build accepts an absolute linker path in NECC_NELINKER. With both tools on your PATH and the same SDK selected, rebuild the C example above using nelinker for its final static link.

export NECC_NELINKER="$(command -v nelinker)"
necc hello.c -o hello
./hello

The SDK’s TinyCC still handles C preprocessing and assembly. When NECC_NELINKER is unset, TinyCC also handles the final link. To see which archive member supplies a symbol, try the direct archive example.

Compiler timings

In the 19 November 2026 static x86-64 Linux shootout, necc improved on its previous release. Other compilers led all six compile-time cases and both generated-program runtime cases. The table shows median milliseconds over 23 warm, interleaved rounds. Each tool had to produce the expected result.

WorkloadPrevious necc (ms)GCC-built necc (ms)Fastest external (ms)
Compile 128 functions16.0388.7271.506 · TinyCC
Run six million arithmetic iterations20.2779.3712.099 · Zig cc -O2

A separate 25-round measurement of the 128-function input put standalone preprocessing at 4.892 ms. TinyCC finished the entire compile in 1.526 ms in that run. For a larger correctness check, necc compiled all 42 C translation units of the Lua runtime and extensions. The resulting interpreter passed the portable Lua 5.4.6 test suite.
