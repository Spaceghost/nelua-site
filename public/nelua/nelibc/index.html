Core

nelibc

A C library, rebuilt piece by piece in Nelua.

Replace selected libc functions with Nelua implementations, using glibc, musl or Cosmopolitan for the rest; or use the standalone runtime with no external libc. Spaceghost/nelibc is experimental, Linux x86-64, with hybrid builds working and the standalone profile in progress. The implementations are Nelua, with x86-64 assembly for memory primitives and C adapters at the runtime boundaries.

Five runtime arrangements

The C interface stays familiar while ownership changes. Compiler choice (GCC, Zig or TinyCC) is a separate axis from the runtime supplying the missing functions.

Who owns the parts Nelibc has not replaced?
ProfileNelibc ownsUnderlying runtime
glibc hybridThe selected Nelua implementations and adaptersGNU libc supplies uncovered APIs and runtime support
musl hybridThe selected Nelua implementations, with musl-specific adaptersmusl supplies uncovered APIs and runtime support
Cosmopolitan hybridMemory, strings, narrow character classification, floating conversion, IP conversion, real and complex mathCosmopolitan owns startup, allocation, FILE streams, threads, filesystem calls, resolver and integer conversion
StandaloneIts own startup, allocator, stdio, threading subset, locale and other implemented APIsLinux x86-64 kernel services; uncovered functionality remains implementation work
HostThe standalone implementations over a callback dispatcherA kernel or embedding host supplies console, memory, clocks, TLS and exit; current pthreads are cooperative lanes on one hardware thread

The Cosmopolitan profile is deliberately narrower than the older hybrids. A FILE stream, allocation or thread must stay with the runtime that owns its state. Removing glibc does not mean removing the fallback libc. Linux x86-64 is the tested platform; cross-platform runtime conformance is not established.

Consumer flags include -O2 -fno-builtin; volatile pointers to noinline direct-call wrappers stop pure-function calls being hoisted out of the loop. The same wrappers are used in every profile. Taking the address of Cosmopolitan 4.0.2’s strstr IFUNC failed in this toolchain; direct calls passed, so this measures the direct-call path and does not establish function-pointer ABI conformance. Loop, pointer-call and checksum overhead is included equally, not subtracted. Buffers are hot and aligned; this is not a DRAM bandwidth, cold-cache, multicore or application throughput result. The record parser is a synthetic combined workload; qsort includes initializing its input, and malloc/free includes writing the first and last byte.

What to optimize next

Start with measured losses in frequently used operations, retain the winning cases, and require correctness before promoting a faster path. This ordering reflects this corpus; it is not a claim about every application's CPU profile.

  1. memchr-absent: Cosmopolitan + Nelibc measured 0.64× baseline speed at 8 bytes. Keep this case in the comparison while testing short, long, aligned and unaligned inputs.
  2. memset: musl / Zig + Nelibc measured 0.71× baseline speed at 8 bytes. Keep this case in the comparison while testing short, long, aligned and unaligned inputs.
  3. snprintf-mixed: glibc + Nelibc measured 0.79× baseline speed. Keep this case in the comparison while testing short, long, aligned and unaligned inputs.

Correctness first: investigate or document the newly failing corpus cases before promoting optimizations: musl / Zig: regression/sigprocmask-internal.

Next evidence: application profiles to weight the cases; more CPUs and working-set sizes; allocator contention and I/O workloads. A single-host microbenchmark cannot establish a globally fastest libc.

7 November 2026 gate
2026-11-07 on main 1c7240a (branch commit d5f3456): Debian 12, glibc 2.36, GCC 12.2, Zig 0.17.0, Nelua dabbd9ef. 159 of 159 targets passed with no warnings: hybrid Zig/glibc, GCC/glibc and Zig/musl, standalone Zig and GCC, freestanding Zig and GCC, the host profile, and musl's libc-test against the hybrid and standalone archives. Until an earlier run that day the gate script had left libc-test out although the repository's gate list includes it; a <limits.h> regression in GCC hybrid builds slipped through that gap and was fixed.
Conformance
musl's libc-test runs against the gcc and zig hybrid archives with a committed expected-failure list that only shrinks: 112 and 118 after the first slice, 31 (gcc) and 35 (zig) in the recorded 2026-11-07 run, none of them math tests. Slice 2 fixed strftime, fnmatch, exact %La, the TZif reader's stack use and malloc_usable_size; the math slice ported musl's exp, pow, log, trigonometric, gamma and Bessel code with its exception-flag discipline, which cleared 76 math tests. A follow-up fixed the last seven: the sign of fma with a zero addend, fmaf rounding and underflow in the subnormal range, the sign of modfl's fraction, and musl ports of erfl, erfcl and exp10l. printf now formats every long double exactly: %Lf, %Le and %Lg write the full decimal expansion of the 80-bit value and round half to even, checked against glibc on 28 cases including LDBL_MAX in all 4,940 characters.
Standalone conformance
libc-test also runs against the standalone archive, where Nelibc is the whole C library: Nelibc's headers only, its own _start, libc-test's own runner with the 100 KiB stack limit. The first run passed 255 of 343 tests with GCC; after the fixes it led to (<limits.h>, <inttypes.h>, <langinfo.h>, <search.h> and <regex.h> (nebox's Pike VM engine behind the POSIX interface) for standalone, static constructors and destructors, scanf %n and ungetc pushback, cancellation points and PI mutex relock, ftello on append streams, sem_open reuse, pthread_create's EAGAIN, exit after the last pthread_exit) 300 pass with GCC and 301 with Zig, with no timeouts; with <pwd.h>/<grp.h>, <setjmp.h> and a batch of small POSIX families since, 326 pass with GCC and 328 with Zig; with iconv (UTF-8/16/32, UCS-2/4, the ISO-8859 and Windows code pages, KOI8, CP437/850, musl's * replacement), shm_open, dn_expand and a GCC <tgmath.h> on top, 332 pass with GCC and 333 with Zig (all 11 and 10 failures expected and listed; one of GCC's is a libc-test main without a return). mktime now honours a tm_isdst that contradicts the date, as glibc and musl do, a fix found through nebox's date -d '14 days ago'. Every math test that builds passes. The rest is a written map of what is missing (dl*, crypt, wordexp, ...) and of what is still open (a posix_spawnp null-envp divergence, destroying a locked robust mutex), in docs/libc-test.md.
