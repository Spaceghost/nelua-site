Core · the linker

nelinker

A static linker written in Nelua for x86-64 Linux executables and UEFI applications.

Give it object files and Unix archives. It resolves symbols, applies relocations and writes an executable. The same linker performs the final link of both itself and the necc compiler driver.

Link an archive

Save start.s and answer.s in the same directory. The entry point calls answer and passes its return value to the Linux exit syscall. With GNU binutils and nelinker on your PATH, build the two objects and put the provider in an archive.

as --64 -o start.o start.s
as --64 -o answer.o answer.s
ar rcs libanswer.a answer.o
nelinker -t -o demo start.o libanswer.a
./demo
echo "$?"

The link trace includes libanswer.a(answer.o). The program exits with status 42. Place an archive after the objects that reference its symbols. Use --start-group and --end-group around archives that depend on one another.

Supported inputs

In Linux mode, nelinker produces fixed-address static executables from x86-64 ELF objects. It reads regular GNU/SysV and BSD archives, resolves strong and weak symbols, and supports static GOT entries and local-exec TLS. PIE, shared libraries, thin archives, LTO and custom linker scripts are outside the current scope.

For C or Nelua programs using nelibc, let necc invoke nelinker. The driver supplies the SDK libraries and their relocation conventions.

Link a PE32+ EFI application

With --efi-app, nelinker reads freestanding x86-64 ELF objects and static archives and writes a PE32+ EFI application. The entry symbol defaults to efi_main. This command links the neboot menu with a preferred load address of 4 GiB.

nelinker --efi-app --image-base 0x100000000 -e efi_main -o BOOTX64.EFI menu.o

The linker records 64-bit absolute image pointers as DIR64 entries in .reloc so firmware can adjust them if it loads the image at another address. The neboot OVMF run shows the address firmware used.

Creating an archive

On 22 November 2026, creating a deterministic archive from 256 x86-64 objects with short filenames took 3.251 ms with native build a349c2a. The earlier TinyCC-built 0c27372 took 3.908 ms. GNU ar took 18.991 ms. The current writer stores ordinary filenames directly in the member header and preserves short filenames containing spaces. The output size fell from 215,484 to 213,376 bytes, matching the GNU archive size.

Archive creation used 31 interleaved warm runs on one Intel Core i5-10400 core. GNU ar listed the members, nm read their index, and both nelinker and GNU ld linked a program that returned 42.
