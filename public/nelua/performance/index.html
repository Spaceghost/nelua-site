LZ4 compresses the Nelua compiler source

Four compilers built the LZ4 1.10.0 block codec. Each build compressed the same 62 Lua files into 430,145 bytes at the default acceleration and restored all 1,141,485 input bytes exactly.

LZ4 reads short, unaligned values with memcpy. Building the codec with necc 7ed048c and -DLZ4_memcpy=__builtin_memcpy eliminated all 59 direct calls to memcpy in its assembly. Fixed-size reads and writes use exact-width instructions. Both necc rows use the same compiler binary.

At acceleration 1, the builtin cut compression time by 14% and decompression time by 28%. At acceleration 4, compression took 6.71 ms and the output grew from 430,145 to 477,127 bytes. GCC and Clang still compressed the default case in under 1.9 ms.

Inputs, method and individual samples

The corpus concatenates tracked Lua files under lualib/nelua at 0f29b8f in Git tree order. Eleven shuffled rounds followed one warm-up on logical CPU 5. Each round rebuilt the object and timed nine in-memory compressions and decompressions per setting. File I/O, linking and verification fall outside the codec intervals.

Toolchains were native necc 7ed048c, its SDK TinyCC, GCC 16.2.1 and Clang 23.1.5. All compiled LZ4 1.10.0 with portable memory access and an equivalent typedef-based static assertion. The common GCC-built driver checked the round trip. Each compressed block matched the reference SHA-256 for its setting.

Nelibc benchmarks

The goal is the fastest correct implementation of the libc operations programs use most. The current evidence compares glibc, musl and Cosmopolitan, each alone and with Nelibc, on the same host and consumer.

Completion

glibc: 819; musl / Zig: 793; Cosmopolitan: 399 of 1,471 tracked names exported by Nelibc. These count owned implementations, not standards compliance. Cosmopolitan deliberately delegates more stateful services.

Conformance

glibc: 301 → 325 passes; musl / Zig: 327 → 333 passes; Cosmopolitan: 279 → 301 passes in the matched functional, regression and math corpus. Build failures, runtime failures and newly failing tests are all reported.

Performance

Synthetic record parser, baseline time ÷ Nelibc time: glibc 1.15×; musl / Zig 3.38×; Cosmopolitan 4.36×. Above 1× is faster. The detailed results include memory, strings, conversion, math, allocation, formatting and sorting, including slower cases and delegated calls.

Timings measured 2026-11-23 UTC over seven comparison rounds. Export and conformance counts are from 21 November. Consumer correctness checks passed before timing.

On an eight-byte search with no match, Cosmopolitan with Nelibc took 2.77 ns, compared with 4.02 ns for previous Nelibc and 2.26 ns for the native runtime. See the timing and correctness controls.
